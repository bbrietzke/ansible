Setting up my network with Ansible

A set of helpful commands and tools to make setting up and maintaining my network a little easier.

Setup

Following Ansible best practices, the project is structured with an inventories folder that contains the list of hosts that you will want to talk to. Each inventory contains the names/ips and usernames of the host machines, along with the various children, which are the groups that the playbooks target to decide what software and configuration gets installed where.

The inventories that are present right now:

  • apartment - the default inventory for the Makefile; has the servers, clients and main groups.
  • basement - the machines in the basement; has the shutdown group.
  • home - the Raspberry Pis (octopi and retropie).
  • kubernetes - the Kubernetes cluster; has the controlplane and workers groups.
  • openclaw - the OpenClaw agent boxes; has the agents group.

All of the Ubuntu machines are expected to be on Ubuntu 26.04 LTS (resolute), which is set with ubuntu_version in the inventories.

Personalization

Additional directories can be added to inventories and set up similar to the ones above depending on how you want things to work or look.

Commands

Everything should be driven through the Makefile. Most targets use the apartment inventory unless you tell it otherwise with DEFAULT_GROUP.

  • make default - Install the base packages and users.
  • make update - Update and upgrade everything.
  • make reboot - REBOOT!
  • make shutdown - Shut down the machines in the shutdown group.
  • make slurm - Install the SLURM controllers and workers.
  • make kube - Install the base packages and set up the NFS servers and clients.
  • make kube-update - Rolling update of the Kubernetes nodes, one at a time.
  • make openclaw - Set up the OpenClaw agent boxes.
  • make docs - Build the docs and upload them to gh-pages.

Extra options for ansible-playbook get passed through with EXE_OPTIONS, and a different inventory can be picked with DEFAULT_GROUP:

make update EXE_OPTIONS=--ask-become-pass
make reboot EXE_OPTIONS="--ask-become-pass --limit eris"
make shutdown DEFAULT_GROUP=basement

Playbook Details

Default

  • default.yml - Installs the base packages (avahi, screen, tmux, zsh) and creates the users, pulling their SSH keys from GitHub; also installs the QEMU guest agent on anything in the qemu group.
  • make default

Updates

  • updates.yml - Does an apt update and dist-upgrade on every machine in the inventory, then cleans up and autoremoves old packages. Does them all at once, and doesn't reboot.
  • make update

Reboot

  • reboot.yml - Well, it reboots the machines; only does two at a time.
  • make reboot

Shutdown

  • shutdown.yml - Shuts down everything in the shutdown group, which only lives in the basement inventory.
  • make shutdown DEFAULT_GROUP=basement

Slurm

  • slurm.yml - Installs the SLURM controller on the controllers group and the SLURM workers on the workers group, and writes the shared slurm config to both.
  • make slurm DEFAULT_GROUP=<inventory>
  • None of the inventories have a controllers group right now, and workers only exists in the kubernetes inventory, so don't point this at that one unless you want SLURM on your Kubernetes nodes.

Kube

  • local_kube.yml - Despite the name, it doesn't install Kubernetes. It installs the base packages on everything, the QEMU guest agent on the qemu group, sets up an NFS server on the servers group (with shared, data_redis and data_jenkins shares) and the NFS client on the clients group.
  • make kube

Kube Update

  • kube_update.yml - Updates the Kubernetes nodes one at a time, workers first and then the control plane. Each node gets drained (ignoring daemon-sets and deleting empty-dir data), apt updated, full-upgraded and autoremoved, rebooted if anything changed, and then uncordoned whether it rebooted or not. It waits for the node to come back and for all the pods to settle before moving on to the next one, and stops everything if a node fails.
  • make kube-update EXE_OPTIONS=--ask-become-pass
  • kubectl runs on the machine you run make from, so its kubeconfig needs to be able to reach the cluster. The kubernetes packages are kept on hold so they only get upgraded through kubeadm.

OpenClaw

  • openclaw-agents.yml - Installs the base packages and users, plus the Prometheus node exporter binary, on the agents group.
  • make openclaw

Roles

The roles live in the roles folder. The ones used by the playbooks above are default, qemu_client, update, nfs_server, nfs_client, slurm, slurmctrl, slurm_conf, kube_node_update and node_exporter_binary.

The rest are there to be pulled into a playbook when I need them: alertmanager, apt_cacher, apt_cacher_client, consul, docker, elasticsearch, java, kube_config, kubernetes, memcached, mqtt, nginx, node_exporter, nodejs, octopi_camera, postgresql, print_server, prometheus, redis, samba_server, subversion and vault.
